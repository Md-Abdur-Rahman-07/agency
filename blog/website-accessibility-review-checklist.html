Website Accessibility Review: A Practical Starting Checklist

15 November 20263 min read

On this page

  1. Choose a representative sample
  2. Follow the keyboard journey
  3. Review meaning as well as appearance
  4. Make forms recoverable
  5. Turn findings into a manageable plan
Explore UI/UX Design ↗
The short answer

Start by testing complete customer tasks with different ways of interacting. Automated checks help, but they do not establish that a website is fully accessible.

Try using your website without a mouse. Can you open the menu, move through a service page and send an enquiry? Now enlarge the text and repeat the task. A layout that looked tidy in a design file may become difficult to use once someone interacts differently.

An accessibility review is most useful when it follows those real tasks. The aim is to identify barriers that stop people understanding information or completing an action. It is not simply to add an accessibility badge or collect a passing score from one tool.

Choose a representative sample

Include the homepage, a service or product page, navigation, a form and any important modal or account workflow. If several templates exist, include more than one. Write down which areas were reviewed so the result is not mistaken for a complete assessment of an entire system.

W3C's Easy Checks resource covers initial checks such as page titles, headings, contrast, keyboard focus, image alternatives and form labels. It also explains that these checks are a first review rather than a comprehensive evaluation. Use them to find useful starting points while recognising the limits of the exercise. [1]

Follow the keyboard journey

Move through the page in order. Check whether the current focus is visible, whether the order makes sense and whether interactive controls work without a pointer. Open and close the navigation and any popup. Someone should be able to return to the task without getting trapped in an unexpected part of the interface.

Record barriers as specific observations. “The site needs accessibility” is hard to assign. “The enquiry dialog opens, but keyboard focus remains behind it” identifies a workflow, an expected behaviour and a place to investigate. Include the browser and steps used so another person can repeat the check.

Review meaning as well as appearance

Headings should describe the page structure, not merely provide a larger font. Links should make sense in context. Images that convey information need an appropriate text alternative, while purely decorative images should not create unnecessary narration. A useful alternative describes the information the image contributes, rather than listing every object in a photograph.

Check what happens when an image is missing or text is enlarged. Instructions such as “press the green button on the right” may become ambiguous. Prefer labels that identify the action clearly and remain useful when presentation changes.

Make forms recoverable

  • Give each input a meaningful label that remains available while typing.
  • Explain required information and unusual formats before the user makes a mistake.
  • Identify the field with an error and explain how to correct it.
  • Preserve valid information when a recoverable error occurs.
  • Make successful submission clear, including what happens next.

Test more than an empty-form submission. Use a long name, a pasted phone number and a mistake in one field after the others are complete. Ask whether the experience helps someone recover, rather than simply refusing the input.

Turn findings into a manageable plan

Group problems by shared component. Fixing a navigation control or a form pattern can help multiple pages, whereas editing each instance separately may leave inconsistent behaviour. Agree who implements the change and how it will be retested.

For a broader assessment, involve people with appropriate accessibility expertise and, where possible, users with disabilities. An initial checklist can reveal obvious obstacles, but it cannot certify conformance or replace a review suited to your audience, technology and obligations.
